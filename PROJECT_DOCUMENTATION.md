# Telangana Weather Analytics Project Documentation

## 1. Project Overview

This project is an end-to-end weather analytics and ETL pipeline for all 33 districts of Telangana, India. It collects current weather observations from the Open-Meteo API, stores the results in SQLite and Excel, calculates state and monthly summaries, and creates dashboard images for the latest observation and historical archives.

The pipeline can run once from the command line, refresh automatically every hour, or run on GitHub Actions every hour.

## 2. Main Features

- Collects temperature, humidity, precipitation, wind speed, weather code, and observation time.
- Requests data for all 33 Telangana districts concurrently using a thread pool.
- Retries failed API requests up to three times.
- Uses cached Excel or SQLite data, followed by built-in fallback values, when live data is unavailable.
- Writes district observations and state summaries to SQLite.
- Writes three report sheets to Excel.
- Rebuilds monthly district aggregates after each update.
- Creates a multi-chart PNG dashboard.
- Archives daily and monthly dashboard images.
- Supports one-time execution and hourly watch mode.
- Runs automatically through GitHub Actions with write permission to the repository.

## 4. Requirements

Install the following before running the project:

- Python 3.11 or a compatible modern Python version.
- Internet access for live Open-Meteo requests.
- Write permission in the project directory.
- Python packages listed in `requirements.txt`.

The required packages are:

- `requests` for HTTP API requests.
- `pandas` for data processing.
- `openpyxl` for Excel workbook input and output.
- `matplotlib` for dashboard generation.

## 6. Run the Pipeline Once

Run the ETL process first:

```powershell
python fetch_weather.py
```

This command:

1. Gets the current date.
2. Sends concurrent requests for the 33 districts.
3. Retries failed requests.
4. Adds fallback records for districts that could not be retrieved.
5. Calculates the Telangana state summary.
6. Updates `data/weather_data.xlsx`.
7. Updates `data/weather_database.db`.
8. Runs `visualize_weather.py` automatically.

You can also run the visualization explicitly:

```powershell
python visualize_weather.py
```

The visualization command reads the latest observation from the Excel workbook and writes the dashboard files described in Section 9.

## 7. Run the Pipeline Hourly

To keep the process running and refresh at the beginning of every hour:

```powershell
python fetch_weather.py --watch
```

The process waits until the next hour after each successful cycle. Stop it with `Ctrl+C`.

The `--watch` option is implemented in `fetch_weather.py`. Without this option, the script performs one cycle and exits.

## 8. Understand the Data Flow

```text
Open-Meteo API
      |
      v
fetch_weather.py
      |
      +--> District records for 33 districts
      |       |
      |       +--> Telangana state summary
      |       +--> SQLite database
      |       +--> Excel workbook
      |
      +--> visualize_weather.py
              |
              +--> Latest dashboard PNG
              +--> Daily chart archive
              +--> Monthly chart archive
```

### 8.1 API collection

`fetch_district_weather()` requests these current Open-Meteo variables:

- `temperature_2m`
- `relative_humidity_2m`
- `precipitation`
- `wind_speed_10m`
- `weather_code`

The request uses each district's latitude and longitude and the API's local timezone setting.

### 8.2 Parallel processing

`fetch_all_telangana_districts()` uses `ThreadPoolExecutor` with up to 10 workers. Results are reordered to match the district list, ensuring all 33 districts are represented even when individual requests fail.

### 8.3 Error handling and fallback order

For each district, the pipeline:

1. Attempts the live API request.
2. Retries up to three times, with increasing waits between attempts.
3. Creates a built-in fallback record if a district still fails.
4. Uses cached Excel or SQLite records if the complete live result is unavailable.
5. Stops without updating output files only when no usable district records exist.

## 9. Output Files

### 9.1 SQLite database

`data/weather_database.db` contains these tables:

#### `district_daily_weather`

Stores district-level observations. Important columns include:

- `date`
- `district`
- `state`
- `temperature_C`
- `humidity_pct`
- `precipitation_mm`
- `wind_speed_kmh`
- `weather_code`
- `observation_time`

The primary key is `(date, district, observation_time)`, allowing multiple observations for a district on the same day while preventing duplicate hourly records.

#### `telangana_state_summary`

Stores one state-level summary per date and observation time. It includes average temperature and humidity, total rainfall, hottest and coolest districts, rainiest district, and windiest district.

#### `monthly_district_summary`

This table is rebuilt from `district_daily_weather` after each ETL update. It contains monthly average, maximum, and minimum temperature, average humidity, and total rainfall for each district.

### 9.2 Excel workbook

`data/weather_data.xlsx` contains these sheets:

- `District_Daily_Data`: district observations. Excel uses the source field name `humidity_%`.
- `Telangana_State_Summary`: state-level summaries.
- `Monthly_Summary`: monthly district aggregates.

Duplicate district rows are removed using `(date, district, observation_time)`. Duplicate state summaries are removed using `(date, observation_time)`.

### 9.3 Dashboard images

`visualize_weather.py` creates three dashboard sections:

1. A line chart comparing temperature across districts and the state average.
2. A temperature-versus-humidity scatter plot with bubble size representing wind speed.
3. A state summary card with the latest calculated metrics.

The files are saved as:

```text
data/weather_dashboard.png
data/daily_charts/weather_dashboard_YYYY-MM-DD.png
data/monthly_charts/monthly_dashboard_YYYY-MM.png
```

## 12. GitHub Actions Automation

The workflow file is `.github/workflows/daily_update.yml`.

It runs:

1. At the start of every hour using the `0 * * * *` schedule.
2. On demand through GitHub Actions `workflow_dispatch`.
3. On an Ubuntu runner with Python 3.11.
4. `fetch_weather.py` and `visualize_weather.py`.
5. A commit and push of changes under `data/`.

The workflow uses:

```yaml
permissions:
  contents: write
```

This permission is required for the workflow to commit generated data and images back to the repository.

To run it manually:

1. Open the repository on GitHub.
2. Select the **Actions** tab.
3. Select **Hourly Weather Data Update**.
4. Select **Run workflow**.
5. Open the generated workflow run to inspect logs.

## 13. Push Local Updates to GitHub

First inspect the working tree:

```powershell
git status
```

Stage and commit updates:

```powershell
git add .
git commit -m "Update weather analytics data and documentation"
```

If GitHub has received an automated update since your last fetch, integrate it before pushing:

```powershell
git -c gc.auto=0 fetch origin
git -c gc.auto=0 rebase origin/main
```

If generated binary files conflict during the rebase, keep the local update while replaying the local commit:

```powershell
git checkout --theirs -- data
git add data
git -c core.editor=true -c gc.auto=0 rebase --continue
```

Push with automatic Git cleanup disabled. This avoids common OneDrive file-lock prompts inside `.git`:

```powershell
git -c gc.auto=0 push origin main
git status --short --branch
```

A successful final status shows:

```text
## main...origin/main
```

## 14. Troubleshooting

### API requests fail

Check internet access. The script retries requests and supplies fallback records. Review warning messages in the terminal for the affected districts.

### The Excel file cannot be opened

Close the workbook in Excel and rerun the pipeline. Excel may lock the file while the script is trying to replace it.

### A dashboard is not generated

Confirm that `data/weather_data.xlsx` exists and contains `District_Daily_Data` rows. Then run:

```powershell
python visualize_weather.py
```

### Git asks whether it should delete a directory under `.git`

OneDrive may temporarily lock Git object directories. Answer `n`, allow the Git operation to finish, and rerun the required command with `-c gc.auto=0`.

### Git says a rebase is already in progress

Check the state first:

```powershell
git status
```

If the conflicts are resolved:

```powershell
git add data
git -c core.editor=true -c gc.auto=0 rebase --continue
```

If the rebase metadata is stale and no rebase is active, remove only the stale metadata and retry:

```powershell
Remove-Item -LiteralPath .git/rebase-merge -Recurse -Force -ErrorAction SilentlyContinue
git -c gc.auto=0 rebase origin/main
```

### Git push is rejected as non-fast-forward

Do not force-push. Fetch and rebase:

```powershell
git -c gc.auto=0 fetch origin
git -c gc.auto=0 rebase origin/main
git -c gc.auto=0 push origin main
```
